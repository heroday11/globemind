# V0.10 前端模块化审计（第一批）

日期：2026-07-10

## 基线

按 Vue 单文件组件行数排序，第一批审计的高复杂页面为：

| 页面 | 行数 | 主要混合职责 |
| --- | ---: | --- |
| `DataAssistant.vue` | 5240 | 会话、流式请求、知识库、报告、多个工作区视图 |
| `GroundNewsDesk.vue` | 4743 | 请求、缓存、筛选、领域归一化、助手上下文、复杂视图 |
| `StoryGraphView.vue` | 3503 | API、图数据转换、图渲染、检查器、助手会话 |
| `GroundNewsHome.vue` | 2943 | 聚合请求、首页编排、多个新闻子视图 |
| `sentimentAnalysis.vue` | 2870 | 请求、指标转换、图表配置、页面状态 |
| `DataService/data-search.vue` | 2577 | 查询状态、结果转换、导出、详情交互 |

这些页面大多直接依赖通用配置或网络客户端，领域格式化函数留在 SFC 内，难以独立测试和复用。当前仓库没有 Vue 组件单测框架，纯逻辑优先使用 Node 内置测试运行器，不新增依赖。

## 本批边界

选择 `GroundNewsDesk.vue` 做第一批真实拆分，保持模板、CSS、路由和后端接口不变。

- `src/features/ground-news/api.js`：集中列表、故事详情和 L2 链接口，拥有 URL、参数名与标识符编码契约。
- `src/features/ground-news/presentation.js`：集中筛选配置、领域标签、日期/百分比格式化、信源倾向归一化和页面路由生成。
- `src/features/ground-news/index.js`：唯一公开入口；页面禁止深层导入 feature 内部文件。
- `tests/ground-news-feature.test.mjs`：覆盖请求参数、端点编码、五类信源归一化及关键展示契约。

拆分后 `GroundNewsDesk.vue` 为 4428 行，页面不再直接导入 `axios`、`API_PREFIX` 或 `resolveApiOrigin`。

## 仍存债务

- `GroundNewsDesk.vue` 仍同时承担异步请求竞态控制、缓存、选中态与助手上下文拼装；下一批应提取 `useGroundNewsDesk` composable，但需要组件级交互测试后再迁移。
- `StoryCover` 仍以内联 render component 存在。其样式与页面 scoped CSS 高度耦合，本批不迁移，避免视觉回归。
- `DataAssistant.vue` 是当前最大页面，应先按会话、知识库、报告三个 feature 做依赖图，再拆 composable 和子视图。
- `StoryGraphView.vue` 的图数据转换适合优先变成纯领域模块，图实例生命周期继续留在页面层。
- 当前前端以 JavaScript 为主，没有 `vue-tsc` 可执行契约；生产构建和 ESLint 只能覆盖语法、模块解析与部分静态错误。
- 当前缺少 Vue 组件级测试工具，模板事件、加载态和请求竞态仍主要由构建与人工 smoke 覆盖。
- 完整 `npm run lint` 当前有 55 个本批范围外的基线错误，集中在 `DataAssistant.vue`、`StoryGraphView.vue`、数据搜索和新闻详情等页面；本批 `GroundNewsDesk`、feature 与测试的聚焦 ESLint 已通过。
- 隔离目录生产构建通过，但仍提示两个绝对路径静态资源需运行时解析，以及 `vendor-echarts` 超过 1 MB 的既有分包警告。

## 后续顺序

1. 为 Ground News 增加页面状态 composable 和最小组件交互测试，再迁移缓存与请求竞态控制。
2. 提取 Story Graph 的响应转换、节点排序和图模型构建，保留 G6/ReactFlow 生命周期在视图适配层。
3. 将 Data Assistant 按会话、知识库、报告拆成独立 feature，只通过各自 `index.js` 暴露能力。
4. 在 ESLint/CI 中增加禁止跨 feature 深层导入的规则，并逐步为每个 feature 建立定向测试入口。
