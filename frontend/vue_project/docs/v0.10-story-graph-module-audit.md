# V0.10 Story Graph 模块化审计（第二批）

日期：2026-07-11

## 本批结果

`StoryGraphView.vue` 拆分前为 3503 行，同时承担请求、响应归一化、图模型、ReactFlow 加载、格式化、助手上下文和页面状态。拆分后页面为 2501 行，只通过 `@/features/story-graph/index.js` 使用 Story Graph 能力。

- `api.js`：统一 L2/L3 列表、工作区详情、节点证据的路径、参数和取消信号契约。
- `model.js`：将 L2/L3 后端响应转换成统一节点、边和 metadata 模型。
- `flow-model.js`：集中节点排序、宏事件 lane 归一化、时间轴位置和合成分支边。
- `presentation.js`：集中列表过滤、指标、摘要、时间和领域标签。
- `config.js`：集中 run ID、视口、handle、颜色和标签等 adapter 配置。
- `story-graph-react-flow.js/.css`：从 `views/` 迁入 feature，由公共入口保持动态加载。
- `index.js`：Story Graph 对页面和其他 feature 的唯一公开入口。

## 已删除遗留

页面内旧 `buildWorkspaceGraph` 及其节点、combo、边样式辅助函数只有定义和内部引用，实际渲染早已使用 ReactFlow adapter。经全仓 `rg` 确认零调用后删除，避免维护两套图模型。同步删除统一 `AssistantDrawer` 接管后未再调用的旧内联流式发送函数；保留当前仍执行的助手上下文和已存在会话读取逻辑。

## 残余职责

- 页面仍负责 Vue 响应式状态、请求竞态/AbortController、选中态、抽屉交互和助手上下文组装。
- 页面模板和 scoped CSS 仍占主要体量；本批为避免视觉回归没有迁移，后续需先补组件级截图和交互测试。
- ReactFlow adapter 仍包含 React 组件、布局编排、手动连边和本地布局持久化，后续可继续按 canvas、node、edge、layout 拆分。
- 助手会话读取仍在路由页直接使用 Assistant API，后续应由独立 assistant feature 接管，避免 Story Graph 反向拥有会话协议。
- 前端尚无 Vue 组件测试框架和 `vue-tsc` 契约；本批使用 Node 内置测试、聚焦 ESLint 和隔离生产构建验收。
- 完整 `npm run lint` 当前剩余 46 个本批范围外错误，集中在 `DataAssistant.vue`、数据搜索、新闻详情等页面；Story Graph 页面、feature、adapter 和测试的聚焦 ESLint 已通过。
- 隔离生产构建通过并继续生成独立 ReactFlow chunk；仍有两个绝对路径资源需运行时解析和 `vendor-echarts` 大包的既有警告。
