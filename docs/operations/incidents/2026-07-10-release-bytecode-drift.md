## 摘要

一次以 `root` 身份运行的生产安全诊断从 `current` 发行目录导入了应用模块。
诊断解释器启动前没有禁用 Python 字节码写入，因此在正式发行目录中生成了 4 个
`__pycache__` 目录和 11 个未列入 `SHA256SUMS` 的 `.pyc` 文件。

Web、隧道和持续运行的管线没有停止，请求也未中断，但当前发行物已不再满足不可变
发布契约。处置没有原地删除异常文件，而是保留原目录作为证据，在旁路重建并完整验证
干净副本后原子替换正式路径。

### 为什么 `0555` 没有阻止写入

`0555` 只通过传统 DAC 权限位阻止普通用户写入。执行诊断的 `root` 进程具有
`CAP_DAC_OVERRIDE`，可以绕过目录缺少写权限的限制。现场也与此一致：父目录保持
`0555`，新建的缓存目录为 `0755`，缓存文件为 `0644`。

因此，`chmod` 是误操作防护，不是面对 root 或等效 capability 的不可变性边界。真正的
边界需要只读挂载，并同时移除运行进程的写入和重新挂载能力。

## 处置与恢复

1. 暂停所有会导入 `current`、版本化发行目录或隔离证据目录的诊断。
2. 只读取证文件时间、所有者、模块路径和 session 记录，没有在原目录删除缓存。
3. 在正式路径之外重建干净副本，仅保留 `SHA256SUMS` 声明的发行内容。
4. 对旁路副本执行完整哈希、额外文件、禁止缓存、版本身份和生产发行验证。
5. 将发生漂移的原目录原子移动到证据目录，再把干净副本原子移动到原版本路径。
   `current` 仍指向相同 build-id 路径，无需切换隧道或中断运行中的管线。

   [`create_release.sh`](../../../deploy/create_release.sh) 在启动 Python 前导出
   `PYTHONDONTWRITEBYTECODE=1`；Python 工具入口在导入本地模块前设置
   `sys.dont_write_bytecode = True`。

   `__pycache__`、`.pyc` 和 `.pyo` 直接失败关闭。即使缓存已被写入清单并重新计算哈希，

3. **回归测试**：[`test_release_tooling.py`](../../../backend/tests/test_release_tooling.py)

## 经验

- Python 防写变量必须在解释器启动前生效；运行后修改环境不是等价保护。
- 发行校验必须同时验证内容哈希、完整文件集合和禁止文件类型。
- `0555` 不能替代权限隔离或只读文件系统。
- 生产诊断属于生产变更，应使用受控入口、最小权限并进行前后完整性验证。
