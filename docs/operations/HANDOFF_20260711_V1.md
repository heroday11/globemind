## 1. 用户目标与执行原则

最终目标不是只改几个页面，而是把 GlobeMind 推进到可持续维护的 V1.0：

- 前后端按页面或业务功能形成高内聚模块，跨模块只依赖稳定公共入口。
- 复杂页面逐步变成编排壳；API、状态、转换、领域逻辑和可复用组件归入 feature。
- 后端路由只处理 HTTP，业务用例、查询、契约和适配器归入 feature/platform/domain 边界。
- 所有常驻服务和不断运行的管线有唯一清单、统一只读状态、强进程身份、检查点、审计和安全生命周期控制。
- 每个版本必须经过聚焦测试、完整质量门禁、候选环境、生产 smoke 和回滚验证。
- 用户要求使用代理团队做有边界的并行重构，由主代理规划、审查和集成，同时控制额度消耗。

资源纪律：一次最多分派三个互不重叠的具体任务；不要重复审计，不要让多个代理修改同一文件；主代理必须保留集成、验收和生产操作权。

## 7. 从 V0.10 到 V1.0 的整改路线

### V0.10：建立可执行的模块与运行时边界

本版本解决“已经有规则，但关键功能仍穿透边界”的问题。

必须完成：

- 同步下降 import boundary 基线并保持零新增债务。
- 完成 V11 搜索对当前 L3/L2/L1 数据模型的兼容适配和契约测试。
- 至少完成 Ground News、Story Graph 两个前端 feature 的构建和页面 smoke；根据风险决定是否把 Data Assistant 第一层 API/state 边界纳入本版。
- 完成当前 V0.10 所有聚焦测试、完整质量门禁和前端生产构建。
- 构建固定 V0.10 Web runtime 和 schema-v3 release。
- 在独立候选端口完成四 worker、worker replacement、代表 API、页面资源和回滚 smoke。
- 验证 V0.9.3 回滚 artifact 后再切换生产；记录发布哈希、运行时指纹、PID/start ticks 和回滚命令。

退出标准：V0.10 生产稳定，功能公共入口门禁通过，旧 V11 路径不再依赖缺失表，统一运行时状态可可信观察。

### V0.11：扩大模块化覆盖并接管主要管线

本版本解决“只有少数 feature 可独立升级、统一管理仍以观察为主”的问题。

必须完成：

- 前端按优先级拆分 Data Assistant、Data Search、Pipeline Monitor、Ground News Home、sentiment；页面只做路由和视图编排。
- 后端形成 assistant、search、operations、financial、opinion 的 feature facade、contracts、application 和 repository/adapter 边界。
- 将环境读取收敛到类型化配置装配层，持续下调 145 条历史债务。
- 为核心页面/API 增加契约测试和最小浏览器 smoke，覆盖登录、搜索、Story Graph、Ground News、助手和管线监控。
- 对 daily ingest、quality labels 以及选定的 Wave1/ground 管线逐个执行检查点、重放、隔离 stop/start 和回滚演练后，才启用统一生命周期动作。
- 清理代理池陈旧身份记录，建立池成员强身份或可验证租约。
- 为 PostgreSQL、Cloudflare、模型服务、代理和关键数据源增加可信探针，区分本地健康、依赖降级和业务停滞。

退出标准：主要页面和后端域可以独立理解、测试和升级；主要常驻管线可在统一界面下安全观察，已通过接管门禁的管线可以审计式控制。

### V1.0：形成生产管理基线

本版本解决“升级仍依赖个人记忆和临时命令”的问题。

必须完成：

- 服务、管线、发布、配置、secret 引用、健康和操作审计均有唯一事实源。
- 所有关键进程具备强身份；控制动作默认失败关闭，禁止 PID-only 信号和宽泛进程匹配。
- 核心 feature 有明确 owner、公共契约、依赖方向、测试入口、健康信号和回滚说明。
- 完成从 V0.11 到 V1.0 的候选发布、worker/tunnel 故障演练、管线检查点恢复演练和 V0.11 回滚演练。
- 完成安全、数据库连接容量、性能、可观测性和数据一致性验收；无未关闭的高严重度生产安全问题。
- 固化新模块开发模板、版本发布清单、事故响应和日常运维手册。

达到这些门槛后，项目管理会有质的提升：模块升级的影响范围更可预测，管线状态和所有权更清楚，发布与回滚不再依赖临时记忆。但 V1.0 不是“以后无需治理”，新增功能仍必须遵守公共入口、测试、健康和回滚门禁。
