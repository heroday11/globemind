## Quality Notes

L1 is the Ground News style story-card/routing layer. It intentionally groups duplicate coverage, previews, outcomes, analysis, and market-context articles around the same short-window story. Final audit showed no non-singleton L1 cluster spanning more than 3 days.

L1.5 preserves full L1 article coverage and splits broad story cards into smaller story-angle segments. It is the safer layer for timeline rendering inside a story card.

L1.5 inherits `location`, `tone`, and fallback title metadata from L1 clusters. Current populated metadata: `location` is non-null on `185,103 / 274,617` segments, and `tone` is non-null on all `274,617` segments.

L2 is an optional storyline/evolution layer. It does not attempt full article coverage. It only links L1.5 segments when there is a reliable actor pair, compatible family/action, bounded time gap, and enough title/topic cohesion. Template noise checks currently return zero matches for known recurring `General Staff` and `France Diplomatie` failure modes.

L2 segment edges now carry explicit quality metadata in `event_l2_chain_segments`:

- `edge_weight`
- `relation_reason`
- `title_similarity`
- `shared_topic_count`
- `gap_days`

L2 chains also carry explicit chain quality metadata in `event_l2_chains`:

- `chain_quality`: `strong`, `usable`, or `watchlist`
- `quality_score`: average edge quality after risk penalties
- `risk_flags`: JSONB list, for example `low_average_edge_weight`, `low_title_overlap`, `weak_edge`, `long_span`

## API / UI

New API endpoints:

- `GET /api/story-graph/ground-news/list`
- `GET /api/story-graph/ground-news/{cluster_id}`
- `GET /api/story-graph/l2-chain/list`
- `GET /api/story-graph/l2-chain/{chain_id}`

Related L2 chains are ordered by `chain_quality` and `quality_score` so story cards prefer strong chains first. `GET /api/story-graph/l2-chain/list` also supports `chain_quality=strong|usable|watchlist`.

New frontend route:

- `/data-service/ground-news-desk`

This page uses L1 as the primary story-card layer, L1.5 as internal sections, and L2 as related trend/timeline chains. The current UI follows a Ground-News-style product structure:

- story headline, event facts, article/source counts
- coverage analysis with left / center / right / state / unknown source spectrum
- blindspot and source-diversity signals
- source columns by political leaning
- L1.5 coverage sections and story timeline
- related L2 chain inspection with edge quality and chain risk flags

Remaining known boundary:

- L2 may still create broad conflict or diplomacy timeline chains, for example daily war developments under the same actor pair. These are acceptable as storyline timelines, not as atomic Ground News story cards.
- The UI/product should use L1 as the primary story card layer, L1.5 as the within-card decomposition layer, and L2 as a related-story/evolution layer.
