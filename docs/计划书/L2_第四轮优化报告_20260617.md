# L2 第四轮优化报告 2026-06-17

## 本轮目标

第三轮之后，L2 主链本体已经比较干净：

- 展示 story 不大
- 单日密度可控
- 纯度显著提升

这时继续对主链做硬切分，收益已经开始下降，风险反而会上升：

- 可能把本来有分析价值的复合危机窗口切碎
- 可能为了追求 purity 指标好看，损失真实事件演化上下文

所以第四轮不再继续“机械切章”，而是补齐分析层表达。

## 本轮改动

代码主改动位于：

- [event_evolution_chain.py](/root/data/globemind/core_pipeline/event_evolution_chain.py:1)
- [story_graph.py](/root/data/globemind/backend/api/routes/story_graph.py:1)
- [test_event_evolution_chain.py](/root/data/globemind/backend/tests/test_event_evolution_chain.py:1)

### 1. 正式引入 `story_relations`

L2 现在除了 `story_edges` 这条展示主链外，还会额外写入 `story_relations` 侧表。

这张表表达的是：

- `backbone`
  story-to-story 的阶段推进关系
- `context`
  story-to-story 的上下文/并行支线/同危机窗口关系

也就是说，L2 现在正式变成：

- 展示层：`cluster -> cluster` 的主链 `story_edges`
- 分析层：`story -> story` 的关系图 `story_relations`

### 2. 关系层的两类 backbone

本轮显式落了两种 backbone 关系：

- `macro_sequence`
  同一个 macro group 内相邻 chapter 的顺序关系
- `pair_sequence`
  同一 entity pair 下相邻 chapter 的顺序关系

这两类关系不会进入当前前端主图渲染，但会为后续分析层提供明确的阶段推进结构。

### 3. 关系层的两类 context

现有 `reference_candidates` 不再只作为 `story_trees.meta` 里的附属字段存在，而是正式写成分析关系：

- `pair_family`
  同一 pair family 的关联 chapter
- `context`
  共享实体、共享危机窗口、弱上下文重叠等关系

这使得 L2 不再只是一个“看起来干净的链”，而是一个“主链清晰、旁路关系可查”的双层结构。

### 4. API 支持按需读取分析关系

`GET /api/story-graph/{story_id}` 新增：

- `include_related=true`
- `related_limit`

返回中新增：

- `meta`
- `related_stories`

默认行为不变，所以现有展示前端不会被破坏；只有分析端显式请求时，才返回 story-level 关系层。

## 本轮判断

### 1. L2 主链已经不需要再继续大动

当前主链版本已经具备几个关键特征：

- 纯度足够高
- 大簇问题已被压住
- 展示密度可控
- 最差尾部问题也从“大混章”下降到少量 `2+1` 小混章

如果继续围绕 purity 机械切分，接下来很容易开始破坏真正有分析价值的复合事件窗口。

### 2. 后续重点应该从“继续切”转向“继续表达”

本轮之后，我认为 L2 最合理的定位已经明确：

- `story_edges`
  负责展示
- `story_relations`
  负责分析

这样就不需要把所有复杂关系都硬塞回主链本体。

### 3. 剩余问题已经不是 L2 主切分缺陷

当前仍然残留的低纯度 story，主要是：

- 少量 `3` 节点 `2+1` 小混章
- 个别 `5-6` 节点复合危机窗口

这类问题继续靠 L2 基础切分规则优化，收益已经不高。
更合理的做法是把它们交给：

- L3/L4 分析层
- context graph
- agent/world model 的解释与预测逻辑

## 当前结论

第四轮之后，我认为：

- **L2 的主链部分已经达到可定版水准**
- **L2 的分析关系层也已经具备继续向上游分析模块供给的能力**

因此，后续如果继续投入精力，我不建议再把重点放在“继续改 L2 主切分”，而是应该转向：

1. 利用 `story_relations` 构建分析层输入
2. 对宏观危机网络做世界模型/Agent 推演
3. 在上层区分“事件链”和“态势网络”，而不是继续把两者混在 L2 里
