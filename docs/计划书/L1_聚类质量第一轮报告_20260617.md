# L1 聚类质量第一轮报告

日期：2026-06-17

## 结论

当前这版 L1 相比旧基线有实质改进，但还不能算“事件级高质量聚类”。

更准确的判断是：

- 作为 `L1 召回/归并层`，已经可用。
- 作为 `最终事件簇`，暂不达标。
- 当前最大问题不是漏合并，而是部分大簇仍然停留在 `战役/阶段` 级，而不是单一事件级。

## 人工质检结论

### 1. 正向结果

当前版本在下面几类情况明显比旧版好：

- 同日跨语言复述稿更容易被并到一起
- topic 预分层造成的小碎片减少了
- rescue 没有明显把不同日期的大故事线重新揉成单簇

从漏合并候选看，剩余问题更多集中在：

- 无实体文章 `entity_pair = →`
- 同日跨语言报道但标题差异很大
- 新闻报道与评论/综述混在一起时的边界不稳

### 2. 主要问题

#### 问题 A：大簇仍然是“阶段级/战役级”，不是单事件级

高风险样本很多都跨 `2-7` 天，而且内部标题已经明显对应多个子事件。

代表样本：

- `1_3845655_e1`
  - `53` 篇
  - `2026-02-27 ~ 2026-03-02`
  - 已混入“开战”“命名行动”“伤亡”“后续威胁”等不同子事件
- `8_3602947`
  - `51` 篇
  - `2026-02-28 ~ 2026-03-03`
  - 实体对多达 `7` 种，明显接近战役簇
- `1_3950791`
  - `26` 篇
  - `2026-04-04 ~ 2026-04-11`
  - 这是连续外交施压过程，不应直接当成单事件簇

判断：

- 当前 L1 对“持续性冲突”和“谈判阶段”仍然偏向按主题/进程聚，而不是按单个事件聚。

#### 问题 B：实体归一化仍然不够稳

样本里还能看到同一事件内部出现多种实体对写法：

- `us→iran`
- `trump→iran`
- `us president donald trump→iran`
- `israel&us→iran`
- `israel→iran`

这有两个后果：

- 一部分本该同簇的文章会被拆开
- 一部分本该分开的文章会因为“主干语义很近”被并进战役簇

#### 问题 C：对“报道”与“背景/评论/综述”区分不够

例如一些大簇里既有：

- 明确的单次动作报道
- 战局综述
- 专家评论
- live/blog 汇总

这会把 L1 从“事件簇”拉向“话题簇”。

## 当前可接受度判断

如果目标是：

- `做后续 L2/L3 的候选事件块`
  - 可以继续用
- `直接作为最终事件对象写入分析层`
  - 不建议

当前 L1 更适合被定义为：

- `high-recall event block`

而不是：

- `high-precision final event cluster`

## 建议的下一步修复优先级

### P1：做 L1 内部二次切分，而不是继续放宽 merge

优先方向：

- 对 `size >= N` 的簇做二次 split
- split 信号优先看：
  - 日期
  - 标题锚点
  - 事件触发词
  - 是否是“行动/伤亡/谈判/回应/延长停火”等不同子动作

核心原则：

- 先解决大簇过宽，再继续追求 recall

### P2：把“评论/综述/live/blog”从硬事件里分开

建议增加文档风格标签，例如：

- `hard_news`
- `live_blog`
- `analysis`
- `backgrounder`

L1 主聚类优先只在 `hard_news` 内强归并，其他类型只弱连接。

### P3：补强实体规范化

优先处理：

- `Trump / US / White House / Trump administration`
- `Israel / Israel&US / US`
- 方向归一和联合主体表示

### P4：保留当前保守 rescue 策略

这轮验证说明：

- rescue 如果过宽，会很快滑回“好看但不纯”
- 当前这版 rescue 是相对合理的下限，不建议再放大

## 最终判断

一句话总结：

当前 L1 已经比旧版更好，但它现在最像“事件候选块”，还不是“事件真簇”。

下一阶段工作的重点，不应该是继续补 merge，而应该是：

- `对大簇做事件级二次切分`
- `把评论/综述从硬事件流里剥离`
- `强化实体规范化`
