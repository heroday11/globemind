# L2 第二轮优化报告 2026-06-17

## 本轮目标

针对上一轮审查中暴露的两个核心问题继续迭代：

1. `chapter` 内部事件类型混杂，阶段纯度不足。
2. `macro` 层头部过度集中，单个宏观组吞掉大量 chapter。

本轮策略不是继续“压图大小”，而是做更强的结构约束：

- 对 chapter 增加类型侵入切分与纯度二次切分。
- 对 macro 层增加时窗切分与规模上限，避免传递式吞并。
- 保留展示主链稳定性，不让图重新膨胀失控。

## 本轮改动

代码主改动位于：

- [event_evolution_chain.py](/root/data/globemind/core_pipeline/event_evolution_chain.py:1)
- [test_event_evolution_chain.py](/root/data/globemind/backend/tests/test_event_evolution_chain.py:1)

### 1. 新增 chapter 纯度约束

新增规则：

- `type intrusion`：当候选事件开始侵入当前章节主导类型，且语义相似度/trigger 一致性不足时，提前断章。
- `impure chapter split`：初步切分完成后，对混合章节做纯度二次切分。
- `short-interval weak consistency`：原来只在同日内做弱一致性判断，现在扩展到 `4` 天内的短间隔漂移。
- `direction reversal gate`：同一实体集合下，如果方向发生反转，例如 `US→Iran` 变成 `Iran→US`，不再默认可无缝延续，而是根据 gap / 类型家族 / trigger 一致性判断是否断章。

### 2. 收紧 small chapter 回填逻辑

上一版 `_repair_small_chapters`` 会把切开的碎片直接并回前后章节，导致边界被重新污染。

本轮改为：

- 只有在 `dominant_type` 一致且 embedding / trigger 一致性足够高时，才允许回填合并。
- 否则宁可保留小片段并在后续被过滤，也不强行缝回大章。

### 3. 给 macro 层加“危机窗口”上限

新增规则：

- 单个 macro group 最多 `12` 个 chapter。
- 单个 macro group 跨度最多 `35` 天。
- 相邻 chapter gap 大于 `7` 天时强制断开。
- 同一 pair family 只有在 `dominant_type` 一致且 embedding 相似度足够高时，才允许强合并。

效果是：

- `macro relation` 仍保留。
- 但不会再出现一个大 crisis 域把几个月的所有 chapter 吞成一个超级宏观组。

### 4. 在元数据中显式拆分 reference 语义

当前没有改表结构，但先在 `story_trees.meta` 里把引用关系拆成：

- `pair_family_neighbors`
- `context_neighbors`
- `reference_neighbors`

这相当于先在算法层把 `display story` 和 `macro/context relation` 的语义拆开，为后续进一步分层打基础。

## 本轮提升

### 1. macro 过度集中问题基本被打掉

最关键的提升是 macro 层集中度大幅下降：

- 最大 macro 从 `81` 个 chapter 降到 `12`
- 头部集中度从 `50.63%` 降到 `6.35%`
- 前 3 个 macro 占比从 `68.75%` 降到 `19.05%`

这说明“超级宏观团簇”问题已经从结构上被压住了。

### 2. chapter 纯度显著提升

平均主导类型纯度从：

- `0.7872` → `0.8669`

而且 `<0.8` 的低纯度 story 数量从：

- `76 / 160` → `55 / 189`

在 story 数量增加的情况下，低纯度比例反而明显下降，这说明纯度改进是真实的，不是靠简单删 story 实现的。

### 3. 展示层仍然稳定

虽然 chapter 数变多，但：

- 最大 story 仍然保持 `12`
- 单日最大密度仍然保持 `4`

说明这轮细化没有把展示层重新打回“大图混乱”的状态。

## 当前剩余问题

### 问题 A：尾部仍有少量 `3-4` 节点混合章

这是当前最主要剩余问题。

特点：

- 节点少
- 时间很近
- 语义上属于同一 crisis window
- 但类型标签混杂

它已经不是“结构不可用”问题，而是“阶段标签精细度不够”问题。

### 问题 B：图仍然是主链，而不是分叉图

当前 `story_edges` 仍然保持：

- 最大出度：`1`
- 最大入度：`1`

优点：

- 展示非常干净。

缺点：

- 对分析层来说仍然缺少并行支线表达。
- `context_neighbors` 目前还在 meta 里，没有进入正式图结构。

### 问题 C：时间精度仍主要是 `date_midpoint`

本轮结构已经稳定，但时序精度还没有本质升级。

因此：

- 展示不挤了。
- 但更细粒度的“同日先后关系”分析能力仍然有限。

## 是否还有继续优化的必要

结论：**有，但优先级已经下降。**

当前 L2 已经达到：

- 展示层正式可用
- 中层故事演化正式可用
- 可作为世界模型 / agent 分析层的中间输入

后续是否继续优化，要看你更重视哪一层。

### 如果目标是“正式展示 + 中层浏览”

当前版本已经足够上线使用。

因为核心风险已经被解决：

- 没有超级大图
- 没有头部 macro 垄断
- 绝大多数 story 尺寸可控

### 如果目标是“高质量分析层输入”

仍然建议继续优化，但方向要变。

下一步优先级建议：

1. `P1`：清理尾部 `3-4` 节点混合章
   具体做法：
   - 对极短 story 引入更强的“单类型优先”规则
   - 对混合型小章尝试直接降级为 context 片段，不进入主链

2. `P1`：把 `context_neighbors` 提升为正式分析关系层
   具体做法：
   - display 继续只画 backbone
   - analysis 使用 `context edges` + `backbone edges`

3. `P2`：补小时级时间或同日内顺序估计
   具体做法：
   - 从 `event_coref_members.published_at` 回写更细时序
   - 没有小时级时，用报道顺序/首发顺序做弱排序

## 最终判断

本轮优化是**实质性进步**，不是表面修补。

最重要的两个结果：

1. `macro 过度集中` 已经基本解决。
2. `chapter 纯度` 已经显著提升。

当前 L2 可以评价为：

**高质量展示级 + 中高质量分析输入级。**

离“惊艳”的差距已经不在大结构，而在最后一层精修：

- 清理少量尾部混合章
- 给分析层补受控分叉和上下文关系
- 提升时间精度

一句话总结：

**L2 已经从“可用”推进到了“很强”，下一步再做的是从“很强”打磨到“惊艳”。**
