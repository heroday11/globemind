# L1 高质量迭代报告

日期：2026-06-17

## 本轮目标

把 L1 从“阶段/战役簇偏多”的状态，快速迭代到更接近“事件级簇”的状态。

优先级排序：

1. 先压缩过宽大簇
2. 保住同日重复稿的基本召回
3. 不再继续放大跨 topic merge

## 本轮改动

核心改动文件：

- [core_pipeline/event_coref_cluster.py](/root/data/globemind/core_pipeline/event_coref_cluster.py)
- [scripts/run_event_level_pipeline.py](/root/data/globemind/scripts/run_event_level_pipeline.py)
- [backend/tests/test_data_processing_basics.py](/root/data/globemind/backend/tests/test_data_processing_basics.py)

本轮实际做了四件事：

### 1. 收紧主聚类时间窗

把原先偏宽的 L1 连边窗口改得更偏事件级：

- `military / protest_repression / terrorism_espionage`
  - `1 天`
- `diplomacy / trade_conflict / policy_legal / appointment_leadership`
  - `2 天`
- 其他
  - `3 天`

目的：

- 减少跨多天的“阶段串联”

### 2. 给桥接边增加约束

在主图构边阶段，增加了两类约束：

- 非精确实体对的桥接边门槛更高
- 每篇文章只保留少量高质量边，避免 hub 把很多相邻事件糊成一个连通块

目的：

- 抑制单条模糊报道把整个话题面串起来

### 3. 改进 impure split

把原先只看“实体对数量是否超过阈值”的粗规则，改成更看重：

- dominant entity-pair 占比
- cluster 内实体对分布纯度

目的：

- 把“一个主事件 + 少量杂质”与“真正的垃圾大簇”区分开

### 4. 增加大簇语义二次切分

新增 `split_broad_semantic_clusters()`：

- 只对偏大的 cluster 启动
- 在簇内重新按
  - 时间接近
  - embedding 相似度
  - 标题相似
  - trigger 相似
  - 实体对一致性
  进行更严格的二次切分

目的：

- 把“战役簇/阶段簇”切回更细的事件簇

## 质量判断

### 明显变好的部分

样本级纯度改善非常明显：

- `span >= 2 天` 的样本簇数量：`14 -> 1`
- `span >= 4 天` 的样本簇数量：`1 -> 0`
- `entity_pairs >= 3` 的样本簇数量：`9 -> 2`
- `size >= 20` 的样本簇数量：`10 -> 1`
- 审计样本最大簇：`53 -> 22`

这说明：

- L1 已经明显从“阶段簇/战役簇”向“事件簇”移动
- 最大问题已经不再是头部大簇失控

### 代价

代价也很明确：

- 非单例簇数量下降较多：`1618 -> 1222`
- 说明这轮是明显的 `高精度换召回`

但结合用户目标来看，这个代价是可接受的，因为本轮优先目标就是：

- `不要数据看起来好看，但内部一致性很差`

## 结论

当前这版应当作为新的 L1 工作基线保留。

原因：

- 事件级纯度提升非常明显
- 最大簇被有效压缩
- 同日高相似漏合并没有恶化，反而略有下降
- 虽然 recall 有所损失，但这是朝“高质量事件簇”迈出的正确方向

一句话总结：

这轮把 L1 从“高召回但偏阶段化”拉到了“更接近事件级高精度”的状态。

## 下一轮建议

下一轮不应该再去放宽主图构边，否则大簇会重新回来。

更好的方向是：

1. 只做 `低风险 duplicate rescue`
   - 目标对象：同日、超高相似、标题几乎相同的小碎片
   - 包括 `entity_pair = →` 的文章

2. 给 `评论 / 综述 / live blog / hard news` 加文档类型标签
   - 这样 L1 可以把报道和综述更好地区分开

3. 对极少数剩余大簇继续做规则细化
   - 当前最大簇已降到 `22`
   - 这时已经可以做有针对性的精修，而不是全局大改
